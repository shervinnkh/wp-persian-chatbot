# قرارداد افزونه ↔ سرور

نسخهٔ قرارداد: `1`. همهٔ بدنه‌ها JSON (UTF-8)، حداکثر ۵ مگابایت. اتصال فقط روی HTTPS (به‌جز توسعهٔ محلی).

## احراز هویت (HMAC-SHA256)

کلید مشترک: `API_SHARED_SECRET` در سرور = `PWC_API_SECRET` در افزونه. کلید هرگز روی شبکه نمی‌رود. زمان مجاز: ±۳۰۰ ثانیه.

| جهت | هدرها | پیام امضاشده |
|---|---|---|
| افزونه → سرور | `X-Timestamp`، `X-Signature` = `hex(HMAC(key, timestamp + "\n" + body))` | بدنهٔ خام |
| سرور → افزونه | `X-PWC-Timestamp`، `X-PWC-Signature` = `sha256=` + `hex(HMAC(key, timestamp + "." + body))` | بدنهٔ خام |

سرور → افزونه یک شناسهٔ یکتا هم می‌فرستد: `X-PWC-Delivery` (نتیجه‌ها) یا `X-PWC-Request` (ابزارها). شناسهٔ تکراری ظرف ۱۵ دقیقه جواب `{"duplicate": true}` می‌گیرد و دوباره پردازش نمی‌شود. کلید وب‌هوک و ابزارها `PLUGIN_CALLBACK_SECRET` است (خالی = کلید مشترک).

## افزونه → سرور (`/v1`)

| متد و مسیر | کار |
|---|---|
| `GET|POST /ping` | بررسی اتصال |
| `POST|PUT|DELETE /knowledge/records` | افزودن، جایگزینی و حذف رکورد دانش (`product:N`، `blog:N`، `page:N`، `text:…`، `file:…`، `site:…`) |
| `GET /knowledge/records[/{id}]` | وضعیت رکوردها |
| `POST /jobs/status` | وضعیت کارها |
| `POST /chat/messages` | ذخیره پیام (و در صورت `generate_ai_answer` تولید پاسخ غیرهمزمان) |
| `POST /chat/messages/batch` | ذخیرهٔ دسته‌ای پیام‌ها به ترتیب |
| `DELETE /conversations/{id}/messages[/{message_id}]` | حذف پیام یا کل گفتگو |
| `POST /get_log`, `POST /get_monitoring`, `GET /storage` | لاگ، مانیتورینگ و مصرف فضا |
| `WS /ws` | اعلان لحظه‌ای (توکن کوتاه‌عمر، فقط اعلان) |

ارسال رکورد و پیام همراه یک `callback` (آدرس و مشخصات وب‌هوک سایت) است. فایل‌ها با لینک امضادار کوتاه‌عمر معرفی می‌شوند و سرور آن را فقط از میزبان `PLUGIN_BASE_URL` می‌گیرد.

## سرور → افزونه (`/wp-json/pwc/v1`)

| متد و مسیر | کار |
|---|---|
| `GET /ai/ping` | تست اتصال؛ جواب: `ok`، `api_version`، `plugin_version` |
| `POST /ai/results` | نتیجهٔ پردازش (حداکثر ۵۰۰ مورد) |
| `GET /ai/file` | دانلود فایل با لینک امضادار |
| `POST /ai/budget` | رویداد سقف هزینه (۸۰٪ و تمام‌شدن) |
| `POST /live/products` | قیمت/موجودی زندهٔ حداکثر ۵ محصول |
| `POST /live/tool` | متن زندهٔ یک ابزار سفارشی |

### `POST /ai/results`

```json
{ "job_id": "…", "delivery_id": "…",
  "results": [ { "id": "product:23", "status": "trained", "rev": "…", "error": "" } ] }
```

`status` ‏`trained` ← `ai_status=2` · `untrained` ← `0` · `failed` ← `1` به `0` برمی‌گردد و خطا لاگ می‌شود. اگر `rev` با نسخهٔ ارسال‌شده نخواند، نتیجهٔ `trained` کهنه است و نادیده گرفته می‌شود. نتیجه‌ها idempotent هستند.

آیتم‌های چت در همین endpoint می‌آیند، با فیلد `kind`:

| `kind` | معنی |
|---|---|
| `chat_messages_saved` | پیام‌ها در سرور ثبت شد (پیش از تولید پاسخ) ← `ai_sent=1` |
| `chat_answer` | متن پاسخ هوش مصنوعی، منابع و برچسب «مارک چت» |

## کدهای وضعیت

`200` موفق (برای ابزارهای زنده، خطای کسب‌وکار هم `200` با `ok:false`) · `400/413/415` بدنه یا حجم نامعتبر · `401` امضا یا زمان نامعتبر · `403` IP یا origin غیرمجاز · `404` پیدا نشد · `429` محدودیت نرخ یا سقف هزینه (`Retry-After`) · `503` صف پر یا سرویس در دسترس نیست. بدنهٔ خطا: `{ "code": "…", "message": "…" }`.

## سازگاری

افزونه و سرور هم‌نسخه (`1.x`) منتشر می‌شوند. تغییر ناسازگار در این قرارداد فقط با افزایش نسخهٔ اصلی انجام می‌شود.
