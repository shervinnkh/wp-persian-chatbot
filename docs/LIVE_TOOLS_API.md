# راهنمای فنی — دو API سمت سایت برای ابزارهای داده زنده (نسخهٔ بک‌اند 0.6.0)

این سند می‌گوید **افزونهٔ وردپرس** چه دو endpoint بنویسد و **هر ورودی/خروجی دقیقاً چه شکلی** باشد تا با کد بک‌اند (`app/services/tools/`) بدون تغییر کار کند.

---

## ۱. تصویر کلی

```
پیام کاربر ──▶ افزونه ──POST /v1/chat/messages──▶ بک‌اند AI
   (همراه: live_product_datas، tools[]، page.id، …)

بک‌اند: دور ۱ AI ─▶ «ابزار X را صدا بزن»
        │
        ├─ POST  {سایت}/wp-json/paia/v1/live/products   (API شمارهٔ ۱ — محصولات)
        └─ POST  {سایت}/wp-json/paia/v1/live/tool       (API شمارهٔ ۲ — ابزارهای داینامیک)
        ▼
   متن نتیجه ─▶ به پرامپت اضافه می‌شود ─▶ دور ۲ AI ─▶ پاسخ نهایی ─▶ callback به افزونه
```

- بک‌اند فقط وقتی ابزار را به AI می‌دهد که افزونه در **همان پیام** مجوزش را فرستاده باشد (بخش ۲).
- هر دو API را **بک‌اند به افزونه** صدا می‌زند (جهت معکوسِ ارسال پیام). آدرس سایت از `PLUGIN_BASE_URL` در `.env` بک‌اند می‌آید و مسیرها از `TOOLS_PRODUCTS_PATH` / `TOOLS_DYNAMIC_PATH`؛ پس اگر مسیرهای شما فرق دارد فقط `.env` بک‌اند را عوض کنید.
- مسیرهای پیش‌فرض:
  - `POST /wp-json/paia/v1/live/products`
  - `POST /wp-json/paia/v1/live/tool`

## ۲. چیزهایی که افزونه همراه هر پیام می‌فرستد

در بدنهٔ `POST /v1/chat/messages` (فقط وقتی `generate_ai_answer=true`):

```jsonc
{
  "generate_ai_answer": true,
  "content": "قیمت این گلدان چنده؟",

  // 1) مجوز داده لایو محصول — "price" و/یا "stock".
  //    نبودن/خالی بودن = سایت داده لایو محصول ندارد ← ابزار محصول به AI داده نمی‌شود.
  "live_product_datas": ["price", "stock"],

  // 2) ابزارهای داینامیکی که مدیر سایت ساخته (هر کدام یک ابزار برای AI)
  "tools": [
    {"id": 0, "title": "خدمات نصب کولر", "description": "اگر درباره هزینه و شرایط خدمات نصب کولر پرسیدند این ابزار را صدا بزن"},
    {"id": 2, "title": "…", "description": "…"}
  ],

  // 3) (اختیاری ولی مفید) شناسهٔ صفحه؛ در صفحهٔ محصول = شناسهٔ محصول
  "page": {"type": "product", "id": 23, "title": "…", "url": "…", "slug": "…"}
}
```

نکته‌ها:
- کلید `description` را به شکل `disciprtion` هم می‌پذیریم (املای فعلی افزونه) — ولی بهتر است `description` بفرستید.
- `id` ابزار عدد یا رشتهٔ کوتاه (`[A-Za-z0-9_.:-]`، حداکثر ۴۰) است. اگر کاملاً عددی باشد **به‌صورت عدد** به API شمارهٔ ۲ برمی‌گردد.
- `title` و `description` عیناً به AI می‌رسند؛ `description` را مثل «چه وقت صدایم بزن» بنویسید.
- هر دو فیلد در هر پیام فرستاده شود (بک‌اند چیزی را بین پیام‌ها نگه نمی‌دارد). حداکثر ۳۰ ابزار پذیرفته می‌شود.

## ۳. احراز هویت (برای هر دو API یکسان)

بک‌اند با **همان الگوریتم callbackهای تکمیل** درخواست را امضا می‌کند (کلید = `PLUGIN_CALLBACK_SECRET`، و اگر خالی باشد همان `api_key` / `API_SHARED_SECRET`):

| هدر | مقدار |
|---|---|
| `X-PAIA-Timestamp` | ثانیهٔ یونیکس (عدد صحیح) |
| `X-PAIA-Signature` | `sha256=` + hex‌ِ `HMAC_SHA256(secret, "{timestamp}.{raw_body}")` |
| `X-PAIA-Request` | شناسهٔ یکتای درخواست (برای لاگ؛ همان `request_id` داخل بدنه) |
| `Content-Type` | `application/json` |

افزونه باید: ① `abs(time() - timestamp) <= 300` ② امضا را با `hash_equals` مقایسه کند ③ فقط روی **بدنهٔ خام** (نه JSON دوباره‌کدگذاری‌شده) ④ در غیر این صورت `401` بدهد و هیچ داده‌ای برنگرداند.

```php
function paia_verify_signed_request( WP_REST_Request $r ): bool {
    $ts  = (string) $r->get_header( 'X-PAIA-Timestamp' );
    $sig = (string) $r->get_header( 'X-PAIA-Signature' );
    if ( ! ctype_digit( $ts ) || abs( time() - (int) $ts ) > 300 ) {
        return false;
    }
    $secret   = PAIA_Settings::api_key(); // همان api_key که در بک‌اند PLUGIN_CALLBACK_SECRET / API_SHARED_SECRET است
    $expected = 'sha256=' . hash_hmac( 'sha256', $ts . '.' . $r->get_body(), $secret );
    return hash_equals( $expected, $sig );
}
```

## ۴. قرارداد مشترک پاسخ

- **حتماً HTTP 200** برای هر نتیجهٔ «کاری» (حتی «محصول پیدا نشد»). کد غیر 200 یعنی «خطای فنی» و بک‌اند فقط پیام عمومی «سایت خطا داد» را به AI می‌دهد.
- بدنهٔ پاسخ JSON با `ok`:
  - موفق: `{"ok": true, ...}`
  - ناموفق ولی قابل‌توضیح: `{"ok": false, "error": "ابزار غیرفعال است"}` — متن `error` (حداکثر ۲۰۰ نویسه، بدون جزئیات داخلی/مسیر/SQL) به AI می‌رسد و AI صادقانه می‌گوید اطلاعات ندارد.
- **Timeout بک‌اند: ۱۰ ثانیه** (`TOOLS_TIMEOUT`)، ریدایرکت دنبال نمی‌شود. هدف: زیر ۱–۲ ثانیه.
- حجم پاسخ حداکثر ۲۵۶KB؛ متن نتیجه بیشتر از ۱۲۰۰۰ نویسه (`TOOLS_MAX_RESULT_CHARS`) بریده می‌شود. هر نویسه = توکن = هزینه؛ **فشرده بنویسید**.
- **کش نکنید** (یا حداکثر چند ثانیه): کل فلسفهٔ این ابزارها «لایو» بودن است.
- ارقام را **لاتین (0-9)** بنویسید.

## ۵. API شمارهٔ ۱ — محصولات (`/live/products`)

### درخواست

```json
POST /wp-json/paia/v1/live/products
{
  "request_id": "9f1c2ab04d7e55aa",
  "fields": ["price", "stock"],
  "products": [
    {"id": 23},
    {"id": 41},
    {"name": "گلدان سفالی بزرگ"}
  ]
}
```

| فیلد | توضیح |
|---|---|
| `fields` | همان `live_product_datas` پیام (زیرمجموعهٔ `price`,`stock`). **فقط همین فیلدها را در پاسخ بیاورید**؛ مثلاً اگر `stock` نیست، موجودی را نفرستید (AI نباید ببیند). |
| `products[]` | حداکثر ۵ مورد (`TOOLS_MAX_PRODUCTS_PER_CALL`). هر مورد **یا** `id` (عدد صحیح، اولویت) **یا** `name`. اگر هر دو باشد `id` را ملاک بگیرید. بک‌اند پیشوند `product:` را قبلاً حذف کرده و فقط عدد می‌فرستد. |
| `name` | فقط وقتی AI شناسه را نمی‌دانسته. جست‌وجوی تقریبی کافی است (ادامه). |

### پاسخ

```json
{ "ok": true, "message": "<یک متن ساختاریافته؛ شکل پایین>" }
```

`message` همان‌طور که هست داخل پرامپت می‌رود؛ پس قالبش را **ثابت و کلید: مقدار** نگه دارید. قالب پیشنهادی (یک بلاک برای هر مورد درخواست، به همان ترتیب درخواست):

```
[درخواست 1] id=23
وضعیت جست‌وجو: پیدا شد
شناسه: 23
عنوان: گلدان سرامیکی سفید مدل آوا
لینک: https://example.com/product/ava-pot/
نوع محصول: ساده
قیمت: 1250000 تومان
قیمت اصلی: 1500000 تومان
حراج: بله — 17% تخفیف — تا 2026-11-20
وضعیت موجودی: موجود
تعداد موجودی: 12
پیش‌سفارش: غیرفعال

[درخواست 2] id=41
وضعیت جست‌وجو: پیدا نشد

[درخواست 3] name=گلدان سفالی بزرگ
وضعیت جست‌وجو: چند نتیجه (حداکثر 3 مورد؛ AI از کاربر می‌پرسد کدام)
- شناسه: 52 | عنوان: گلدان سفالی بزرگ طرح لیلی | قیمت: 890000 تومان | وضعیت موجودی: موجود
- شناسه: 58 | عنوان: گلدان سفالی بزرگ طرح گل | قیمت: 940000 تومان | وضعیت موجودی: ناموجود
```

قواعد محتوا:

| بخش | قاعده |
|---|---|
| **وضعیت جست‌وجو** | یکی از: `پیدا شد` · `پیدا نشد` · `چند نتیجه`. برای `name` اگر دقیقاً یک نتیجهٔ مطمئن بود `پیدا شد`، اگر چند نتیجه بود حداکثر ۳ مورد خلاصه، و اگر هیچ نبود `پیدا نشد`. |
| **قیمت** (`price`) | قیمت **فعلی قابل‌پرداخت** + **واحد پول صریح** (تومان/ریال — از تنظیمات ووکامرس). بدون جداکنندهٔ هزارگان تا اشتباه خوانده نشود. اگر محصول حراج است `قیمت اصلی`، `حراج: بله`، درصد تخفیف و در صورت زمان‌بندی، تاریخ پایان را بدهید؛ وگرنه `حراج: خیر`. محصول متغیر: `قیمت: از 800000 تا 1200000 تومان` (و در صورت لزوم ردیف‌های متغیرها). اگر قیمت تعیین نشده (تماس بگیرید): `قیمت: ثبت نشده`. |
| **موجودی** (`stock`) | `وضعیت موجودی`: `موجود` · `ناموجود` · `پیش‌سفارش`. `تعداد موجودی`: فقط وقتی مدیریت موجودی فعال است (عدد)؛ وگرنه کلاً نیاورید. `پیش‌سفارش`: `فعال` / `غیرفعال` / `فعال (با اطلاع‌رسانی)`. |
| **مشترک** | `شناسه`، `عنوان`، `لینک` همیشه (AI لینک را عیناً به کاربر می‌دهد). |
| **حذف** | فیلد ناشناخته/فعال‌نبودن را خالی ننویسید؛ کلاً حذف کنید. |
| **امنیت** | فقط محصولات منتشرشده و قابل‌مشاهده (`publish`، نه خصوصی/پیش‌نویس/رمزدار)؛ هیچ اطلاعات داخلی (قیمت خرید، SKU انبار، یادداشت مدیر) نیاید. |

### جست‌وجوی نام

- ابتدا تطابق دقیق عنوان؛ سپس `wc_get_products(['s'=>$name, 'limit'=>3, 'status'=>'publish'])` یا `WP_Query` با `s`.
- نام را قبل از جست‌وجو نرمال کنید: `ي→ی`، `ك→ک`، ارقام عربی/فارسی → لاتین، فاصلهٔ اضافه.
- نتیجهٔ نامطمئن را «پیدا شد» نزنید؛ «چند نتیجه» بدهید.

### اسکلت پیاده‌سازی (ووکامرس)

```php
register_rest_route( 'paia/v1', '/live/products', [
    'methods'             => 'POST',
    'permission_callback' => 'paia_verify_signed_request',
    'callback'            => function ( WP_REST_Request $r ) {
        $p        = $r->get_json_params();
        $fields   = array_values( array_intersect( (array) ( $p['fields'] ?? [] ), [ 'price', 'stock' ] ) );
        $requests = array_slice( (array) ( $p['products'] ?? [] ), 0, 5 );
        if ( ! $fields || ! $requests ) {
            return [ 'ok' => false, 'error' => 'درخواست نامعتبر' ];
        }
        $blocks = [];
        foreach ( $requests as $i => $q ) {
            $blocks[] = PAIA_LiveProducts::render_block( $i + 1, $q, $fields ); // قالب بخش ۵
        }
        return [ 'ok' => true, 'message' => implode( "\n\n", $blocks ) ];
    },
] );
```

نمونهٔ منطق قیمت/موجودی داخل `render_block` (ووکامرس):

```php
$product = wc_get_product( (int) $q['id'] );
if ( ! $product || 'publish' !== $product->get_status() ) { /* «پیدا نشد» */ }

// قیمت
$cur   = get_woocommerce_currency(); // IRT → تومان ، IRR → ریال (نگاشت خودتان)
if ( $product->is_type( 'variable' ) ) {
    $min = $product->get_variation_price( 'min', true );
    $max = $product->get_variation_price( 'max', true );
} else {
    $now     = wc_get_price_to_display( $product );
    $regular = wc_get_price_to_display( $product, [ 'price' => $product->get_regular_price() ] );
}
$on_sale = $product->is_on_sale();
$sale_to = $product->get_date_on_sale_to(); // WC_DateTime|null

// موجودی
$status  = $product->get_stock_status();        // instock | outofstock | onbackorder
$managed = $product->managing_stock();
$qty     = $managed ? $product->get_stock_quantity() : null;
$backord = $product->backorders_allowed();      // true/false
```

## ۶. API شمارهٔ ۲ — ابزارهای داینامیک (`/live/tool`)

یک endpoint ثابت برای همهٔ ابزارها؛ بک‌اند فقط **شناسهٔ ابزار** را می‌فرستد و **متن** را می‌گیرد.

### درخواست

```json
POST /wp-json/paia/v1/live/tool
{ "request_id": "1b7d0c5e9a3f44d2", "tool_id": 0 }
```

`tool_id` همان `id` ابزار در فهرست `tools` پیام است (عدد، یا رشتهٔ کوتاه اگر غیرعددی تعریف شده باشد).

### پاسخ

```json
{ "ok": true, "text": "هزینهٔ نصب کولر گازی اسپلیت تا 12000 BTU: 1500000 تومان …\nشرایط: …" }
```

یا

```json
{ "ok": false, "error": "این ابزار وجود ندارد یا غیرفعال است" }
```

قواعد:
- `text` **متن ساده** است (نه HTML)؛ همان متنی که مدیر در پنل نوشته، **هر بار زنده از دیتابیس** (ویرایش مدیر باید همان لحظه اثر کند).
- `text` خالی = خطا (بک‌اند آن را «اطلاعاتی نیست» حساب می‌کند). اگر ابزار حذف/غیرفعال شده `ok:false` بدهید.
- ابزار را با `tool_id` در **جدول/آپشن خود افزونه** پیدا کنید؛ هرگز `tool_id` را مستقیم در SQL/مسیر فایل نگذارید (فقط `prepare` یا `absint`).
- متن طولانی مجاز است ولی تا ۱۲۰۰۰ نویسه؛ بیشتر بریده می‌شود. متن را مرتب (سرتیتر کوتاه + خط‌های «کلید: مقدار») بنویسید تا AI دقیق‌تر بخواند.
- نیازی نیست بدانید پیام کاربر چه بوده؛ تشخیص «چه وقت صدا بزنم» با `description` ابزار و AI است.

### اسکلت

```php
register_rest_route( 'paia/v1', '/live/tool', [
    'methods'             => 'POST',
    'permission_callback' => 'paia_verify_signed_request',
    'callback'            => function ( WP_REST_Request $r ) {
        $id   = $r->get_json_params()['tool_id'] ?? null;
        $tool = PAIA_DynamicTools::find( $id );          // null اگر نبود/غیرفعال
        if ( ! $tool ) {
            return [ 'ok' => false, 'error' => 'این ابزار وجود ندارد یا غیرفعال است' ];
        }
        return [ 'ok' => true, 'text' => (string) $tool['text'] ];
    },
] );
```

## ۷. رفتار AI که باید بدانید

- AI **ابزار محصول** را وقتی صدا می‌زند که کاربر دربارهٔ قیمت، حراج/تخفیف، موجودی بودن، تعداد موجودی یا پیش‌سفارش بپرسد — و **فقط برای فیلدهایی که `live_product_datas` اجازه داده**. اگر مثلاً فقط `price` مجاز باشد و کاربر موجودی بپرسد، AI می‌گوید این اطلاعات لایو را نمی‌دهد و لینک صفحه را می‌دهد.
- شناسهٔ محصول را از منابع دانش (`id="product:23"`) یا `page.id` برمی‌دارد؛ اگر نداشت **نام** می‌فرستد (آن‌وقت جست‌وجوی تقریبی شما مهم می‌شود). اگر چند محصول یک‌جا پرسیده شود، همه را در **یک** فراخوانی می‌فرستد.
- مقدارها را **عیناً** از `message` به کاربر می‌گوید (گرد نمی‌کند/تبدیل نمی‌کند)؛ پس واحد پول را حتماً بنویسید.
- حداکثر ۲ بار AI صدا زده می‌شود (K=2): دور اول ابزار می‌خواهد، دور دوم **حتماً** جواب می‌دهد. اگر API شما خطا داد یا جواب ناکافی بود، AI از خودش چیزی نمی‌سازد و می‌گوید اطلاعات ندارد.
- محتوای `message` / `text` برای AI «داده» است نه دستور؛ ولی بهتر است متن‌هایی که کاربران سایت (نظرات، توضیحات) نوشته‌اند را داخلشان نیاورید.

## ۸. چک‌لیست پیاده‌سازی افزونه

1. دو route با `permission_callback` امضا (بخش ۳).
2. در `POST /v1/chat/messages`: `live_product_datas`، `tools[]` (و در صورت امکان `page.id`) همراه هر پیام.
3. API محصولات: id اولویت، نام تقریبی، فقط `fields` مجاز، واحد پول، فقط محصول منتشرشده.
4. API داینامیک: متن زنده از دیتابیس، `ok:false` برای ابزار ناموجود/غیرفعال.
5. هر دو سریع (زیر ۲ ثانیه) و بدون کش طولانی؛ همیشه HTTP 200 برای نتایج کاری.
6. مسیرها یا `.env` بک‌اند را هماهنگ کنید (`TOOLS_PRODUCTS_PATH` / `TOOLS_DYNAMIC_PATH`) و `PLUGIN_BASE_URL` را روی آدرس واقعی سایت (در production فقط https) بگذارید.

برای آزمایش دستی امضا (مثال): `ts=$(date +%s); body='{"request_id":"t","tool_id":0}'; sig="sha256=$(printf '%s.%s' "$ts" "$body" | openssl dgst -sha256 -hmac "$SECRET" | sed 's/^.* //')"` و ارسال با هدرهای `X-PAIA-Timestamp: $ts` و `X-PAIA-Signature: $sig`.
